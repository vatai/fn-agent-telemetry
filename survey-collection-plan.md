# Goal

Collect detailed local usage information from Codex, Claude Code, opencode, and the Antigravity CLI (`agy`) through their native integrations.

# Specification

- Observe local Codex, Claude Code, opencode, and Antigravity CLI (`agy`) sessions, including interactive and non-interactive terminal sessions.
- Install integrations in per-user agent configuration.
- Capture session lifecycle, prompts, tool activity, tool inputs and outputs, assistant output, errors, and raw native event payloads.
- Append plaintext JSONL telemetry indefinitely to the path configured by `AGENT_TELEMETRY_LOG`.
- Telemetry failures must never interrupt an agent session.
- IDE and cloud sessions are out of scope.

# Plan/Steps

1. Implement a shared `agent-telemetry-hook` executable that receives native hook payloads on stdin and writes enriched JSONL events.
2. Add separate Codex and Claude Code adapters that normalize native lifecycle and tool events while retaining raw payloads.
3. Add an opencode plugin under `plugins/opencode/`: a JS/TS module exporting a `Plugin` function (`@opencode-ai/plugin`, locally 1.17.9 against an opencode binary at 1.18.25 — pin it and check the hook surface against the installed binary) that returns hooks. Subscribe to the catch-all `event` hook for lifecycle (`session.created`, `session.idle`, `session.error`, `session.compacted`, `session.deleted`, `message.updated`, `message.part.updated`, `permission.asked`, `file.edited`, `command.executed`) plus the direct `chat.message`, `tool.execute.before`, and `tool.execute.after` hooks.
4. Write opencode events in-process from the plugin instead of spawning `agent-telemetry-hook` per event. Rationale: opencode has no stdin-per-event subprocess contract like Claude Code's `hooks.json`; a plugin is a module loaded into one long-lived Bun process. The opencode side shares the *schema* — `SCHEMA_VERSION`, `event_id`, `timestamp`, `agent`, `host`, `event_type`, `native_event`, `session_id`, `cwd`, `raw`, and the same `AGENT_TELEMETRY_LOG` append-only JSONL target — not the code. Open question: `message.part.updated` is expected to fire per streaming delta — measure the rate before finalizing, and coalesce or sample if needed.
5. Map opencode events onto the shared taxonomy and resolve the asymmetries: no direct `session_end` (candidates `session.idle`, `session.deleted`, the `dispose` hook), and opencode-only signals (`session.error`, `permission.asked`/`permission.replied`, `file.edited`, `command.executed`) that need either new `event_type` values shared across agents or an explicit drop.
6. Capture assistant output from opencode, via assistant message parts (`message.part.updated`) and `experimental.text.complete`.
7. Add an `antigravity-cli` adapter plus a plugin bundle under `plugins/antigravity-cli/`. `agy` hooks use the same shape as Claude Code's — one native payload as JSON on stdin, per event, invoked as a `{"type": "command", "command": ..., "timeout": ...}` handler — so they reuse the existing `agent-telemetry-hook` executable and need only a new adapter. Two shape differences: `hooks.json` maps a *hook name* to its event config (`{"agent-telemetry": {"PostToolUse": [{"matcher": "*", "hooks": [...]}]}}`) rather than mapping event names at the top level, and payload fields are camelCase.
8. Resolve the `agy` stdout contract before enabling any gating hook. Claude Code telemetry deliberately writes nothing to stdout, but `agy` expects a JSON reply and marks `decision` **required** for `PreToolUse` (`allow`/`deny`/`ask`/`force_ask`/`deny_unless_prior_grant`) and for `Stop` (`continue` re-enters the loop). Telemetry must stay observation-only: never blanket-emit `allow`, which would silently auto-approve every tool call, and never emit `ask`, which would force prompts. `PostInvocation` is not `decision`-required but still controls flow via `terminationBehavior` (`force_continue`/`terminate`), and `PreInvocation` can inject steps. The only event whose documented output is `{}` is `PostToolUse`, so register there first; add the others once the behaviour of an empty or absent reply has been measured.
9. Map `agy`'s five events onto the shared taxonomy. Available: `PreToolUse` → `tool_pre` (`toolCall.name`, `toolCall.args`, `stepIdx`), `PostToolUse` → `tool_post` (adds `error`), `PreInvocation`/`PostInvocation` (`invocationNum`, `initialNumSteps`) and `Stop` (`executionNum`, `terminationReason`, `error`, `fullyIdle`). Common fields map as `conversationId` → `session_id`, `workspacePaths` (an array) → `cwd`, `transcriptPath` → `transcript_path`, plus `artifactDirectoryPath` and `modelName`. Missing entirely: `session_start`, `session_end`, `user_prompt`, `notification`, `compact`, `subagent_end` — decide which are proxied (`PreInvocation` with `invocationNum == 0`; `Stop` with `fullyIdle == true`) and which are simply absent. Assistant output is recoverable from the `transcript.jsonl` at `transcriptPath`; `agy -p --output-format stream-json` is a second, non-interactive capture path worth evaluating.
10. Add per-user installation and status commands for all four agents (Codex, Claude Code, opencode, `agy`) that validate CLI support, merge telemetry-only configuration, and validate the log path. opencode installs either as a file in `~/.config/opencode/plugins/` (auto-loaded at startup) or as an npm package name in the `plugin` array of `~/.config/opencode/opencode.jsonc`. `agy` installs as a plugin bundle staged at `~/.gemini/antigravity-cli/plugins/<name>/` (`plugin.json` + `hooks.json`), or by merging hooks into `~/.gemini/config/hooks.json` or `settings.json`; `/hooks` in the TUI lists what is loaded. The Claude Code marketplace manifest is not involved in either.
11. Test event normalization, transcript retention, non-blocking failures, and idempotent installation for all four agents.
